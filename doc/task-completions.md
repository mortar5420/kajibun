# 家事の実施記録と月次集計

## 用語と保存先

| 用語 | このアプリでの定義 | 保存先 |
|---|---|---|
| 担当者 | 現在、その家事を実施する予定のユーザ | `tasks.assignee_user_id` |
| 実施者 | その回の家事を実際に実施したユーザ。初期版は「終わった」を押したログインユーザを実施者として扱う | `task_completions.performed_by_user_id` |
| 実施記録 | 家事を1回実施した事実。実施者、日時、当時の家事名、期限、巻き取りの判定根拠を保持する | `task_completions` |
| 変更履歴 | 誰が、いつ、家事にどんな操作・変更をしたかの記録 | `task_events` |
| 完了イベント | 完了という出来事を表す変更履歴の1件。実施記録のIDを参照し、次回担当者への通知につなぐ | `task_events` の `TaskCompleted` |
| 期限後の巻き取り | 期限日の翌日以降に、担当者から別ユーザへ引き取られ、元担当者以外が実施を完了したこと | 実施記録の `classification = overdue_takeover` |
| 判定不明 | 過去の担当変更などに当時の期限がなく、巻き取りかを確実に判定できないこと | 実施記録の `classification = unknown` |

実施記録が実施内容・集計の正本。変更履歴は経緯の確認に使用する。
完了イベントは実施記録の全項目を複製せず、`completionId` と既存の通知に必要な家事名・次回担当者・次回期限などを持つ。

## 記録と判定

- 「終わった」1回につき実施記録1件。自分が担当している家事だけ完了できる。
- 初期版は操作時刻を実施日時とする。UTCで保存し、月次集計・期限超過判定・画面表示は日本時間を使う。
- 期限当日の引き取りは通常扱い。期限前の担当変更後に期限を過ぎて完了しても、期限後の巻き取りにはしない。
- 担当未設定・期限未設定からの引き取りも通常扱い。
- 前回完了から今回完了までの担当変更を時系列で確認し、最初の期限後の引き取り時点の元担当者・日時・期限を保持する。
- その後の期限変更で判定根拠を上書きしない。元担当者へ戻って本人が完了した場合は通常扱い。
- 引き取りだけでは実施件数に含めない。巻き取り件数は完了した実施件数の内数。
- 完了後は実施日＋繰り返し日数を次回期限とし、実施者の相手に担当を移す。
- 完了済みの実施記録は、家事の改名・削除によって変えない。ユーザ名は現在のプロフィールから表示する。

## データモデルの変更

- `tasks` は現在の状態を引き続き持ち、競合検出のため `version` を追加。
- `task_completions` を追加。家事との対応、実施者、実施日時、家事名・期限の保存値、巻き取り元・日時・当時の期限、判定を保持する。
- `TaskReassigned` に変更時点の `dueDate` を追加。完了イベントの `completionId` で実施記録を参照する。
- 完了時の家事更新・実施記録作成・完了イベント保存は、D1のバッチで一体として成功または取り消す。通知処理は保存成功後に行う。
- 他の担当・期限・削除操作も、更新番号の照合と変更履歴の保存を一体化する。
- 月次集計専用テーブルは作らず、実施記録を対象月で抽出して集計する。

## APIと画面

- `GET /api/completions?month=YYYY-MM`：対象月の合計、ユーザ別・家事別集計、実施記録の明細。認証必須。
- 月の指定を省略した場合は日本時間の当月。月初0時以上、翌月初0時未満の実施日時を集計する。
- `PATCH /api/tasks/:id/complete`：本文に一覧で取得した `{ "version": 数値 }` を指定する。同時更新や同じ完了の再送は `409 task_conflict`。
- 「実施記録」画面で月を選択し、ユーザ別の積み上げ棒グラフ・家事別件数・実施記録を確認できる。
- 通常は青、期限後の巻き取りはオレンジ、判定不明は灰色。色に加えてラベルと件数を表示する。
- 家事別集計は同じ家事IDをまとめ、その月の最新の実施記録の家事名を表示する。各明細にはそれぞれの実施時点の家事名を表示する。

## 移行と検証

`0009_create_task_completions.sql` をアプリ更新に先行して適用する。
移行処理とアプリ更新の間は完了操作を停止する。旧アプリがその間に作った完了イベントは、移行時の実施記録作成に含まれないため。
既存の `TaskCompleted` を実施記録へ移行し、元イベントIDを一意に保存する。
当時の期限・巻き取り元は推測せず、移行済み記録は判定不明として実施件数に含める。
更新前から継続中の家事も、その回に期限のない旧形式の担当変更履歴があれば判定不明とする。

テストでは日本時間の日・月境界、期限前の変更、担当の戻し、期限変更後の判定保持、過去データの移行、改名・削除後の保持、再送・同時完了、保存失敗時の取り消しを確認する。
本番・開発環境へのDB移行適用とデプロイは、このPRの作成とは別の作業。
